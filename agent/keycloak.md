Отлично! Раз код успешно скомпилировался, давайте протестируем всю цепочку авторизации через Postman.
Поскольку мы развернули полноценную инфраструктуру, нам нужно сначала получить токен от Keycloak, а затем отправить его в наш Rust бэкенд через Nginx Gateway.
Вот пошаговый план проверки:
------------------------------
## Шаг 1: Создание тестового пользователя в Keycloak (если еще не сделали)

   1. Откройте админку Keycloak: http://localhost:8081 (логин: admin, пароль: SuperAdminPassword123!).
   2. В левом верхнем углу выберите ваш созданный Realm (например, my-production-realm).
   3. Перейдите в раздел Users -> нажмите Add user.
   4. Введите Username (например, testuser) и нажмите Create.
   5. Перейдите на вкладку Credentials этого пользователя, нажмите Set password.
   6. Введите пароль (например, password123), выключите тумблер Temporary (чтобы Keycloak не требовал смены пароля при первом входе) и нажмите Save.

------------------------------
## Шаг 2: Получение Access Token (JWT) через Postman
В промышленной разработке для этого используется протокол OAuth2. Мы запросим токен по типу Password Grant (самый простой способ для тестирования API).

   1. Откройте Postman и создайте новый POST запрос.
   2. Вставьте URL:
   
   http://localhost:8080/auth/realms/my-production-realm/protocol/openid-connect/token
   
   (Обратите внимание: мы идем через порт 8080 нашего Nginx Gateway, проверяя, что роутинг /auth/ работает правильно).
   3. Перейдите на вкладку Body, выберите тип x-www-form-urlencoded.
   4. Добавьте следующие Key-Value пары:
   * client_id : backend-client
      * username : testuser
      * password : password123
      * grant_type : password
   5. Нажмите Send.

Результат: В ответе от Keycloak вы должны получить JSON-объект. Найдите в нем поле access_token — это длинная строка (JWT). Скопируйте её полностью.
------------------------------
## Шаг 3: Проверка защищенного маршрута в Rust
Теперь проверим, как наш Rust-бэкенд реагирует на запросы без токена и с валидным токеном.
## Тест А: Запрос без токена (Ожидаем ошибку 401)

   1. Создайте в Postman новый GET запрос.
   2. URL: http://localhost:8080/api/backend/protected-data
   3. Нажмите Send.
   4. Результат: Статус ответа должен быть 401 Unauthorized. Это значит, что наш Middleware успешно заблокировал доступ.

## Тест Б: Запрос с валидным токеном (Ожидаем успех 200)

   1. В том же GET-запросе перейдите на вкладку Authorization.
   2. В выпадающем списке Auth Type выберите Bearer Token.
   3. В поле Token вставьте тот самый access_token, который вы скопировали на Шаге 2.
   4. Нажмите Send.
   5. Результат: Статус ответа 200 OK, а в теле ответа вы увидите строку:
   
   This is verified production data from Rust backend!
   
   
------------------------------
## Что делать, если что-то пошло не так?
Если вместо успешного ответа вы получаете ошибки, проверьте логи контейнеров командой docker-compose logs -f backend или docker-compose logs -f gateway:

* Ошибка 401 Unauthorized даже с токеном: Скорее всего, токен протух (по умолчанию у Keycloak время жизни токена — 5 минут, запросите новый на Шаге 2) или в коде Rust не совпадает iss (Issuer). Убедитесь, что в main.rs URL http://keycloak:8080/realms/my-production-realm в точности совпадает со значением iss внутри токена (токен можно расшифровать визуально на сайте jwt.io).
* Ошибка 500 Internal Server Error: Бэкенд на Rust не смог достучаться до Keycloak по внутренней сети Docker, чтобы забрать JWKS-ключи. Убедитесь, что оба контейнера находятся в одной сети internal_network и Keycloak запущен.

Если тесты прошли успешно, мы можем двигаться дальше. Что настроим следующим шагом:

* Показать, как извлечь имя пользователя (preferred_username) или его ID прямо внутри функции get_protected_data в Rust?
* Добавить кэширование JWKS ключей, чтобы бэкенд не слал запросы в Keycloak при каждом клике пользователя?
